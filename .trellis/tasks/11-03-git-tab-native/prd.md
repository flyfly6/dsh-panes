# T6 — Git tab：冻结 fork 为自有基线，并把它的样式收进工作台

> 父任务 `11-03-workspace-v02`。**决策已定（2026-11-03，用户）**：git tab 先保持现状；从此以当前 fork 的代码为基准开发自己的版本，**不再同步上游**。本任务负责「把它变成我们的代码」：先样式对齐，必要时用本插件技术栈重构。
>
> 与 T1–T5 独立：不动客户端其它 tab，也不改宿主半的路由契约。

## Goal

`git` tab 现在是 fork 进来的 `dsh-ide-git` v0.21.1 面板：功能齐（分支树 / 提交图谱 / 变更分组 / 提交框 / 动作条 / diff / 撤回），但**视觉是另一个产品的**——它用上游自己的密度、颜色与 CSS 变量，和设计稿 P3/D3 及工作台的 token 表对不上。同时它是 16.5k 行预编译 JS，改一处样式要在压缩代码里找类名。

本任务把这条线收尾成「我们自己的 git 客户端」：

1. **所有权**：仓库内这份代码成为唯一基线，`UPSTREAM.md` 从「同步手册」改成「来源与署名记录」，不再有 re-sync 流程。
2. **样式**：对齐设计稿 §2.0b 的 token、密度与明暗两套；面板里不再出现上游自带的主色/字号。
3. **结构**：样式对齐后仍不可维护的部分，按我们的技术栈（React 18 TSX + Tailwind token + shadcn 原语 + 已有 shiki）逐块抽出来，直到上游文件只剩数据层与图谱算法，或完全退役。

## Background — 已确认的事实

- **基线**：`src/git/panel.js`（16,513 行，来自上游 `src/client.js` v0.21.1）+ `src/git/host.js`（2,253 行）；宿主半被 `ctx.plugin(gitHost, config)` 挂载，保留 `/dsh-ide-git/api/<method>` 全部方法与守卫（argv-only、同仓串行、`confirm:true`、400 KB diff 截断）。
- **我们的改动**：10 处 `[workbench-fork]`（client） + 6 处（host）：座位注册全删、row config 外移、命名空间改名、远控开关、空仓库兜底。改动点全表在 `src/git/UPSTREAM.md`。
- **上游不可复用为组件**：它的 client bundle 只 `return { name, inject, apply }`，面板组件（`Panel` / `LocaleLive`）在 factory 闭包里，没有服务、没有类型出口。要拿它的 UI 只能自己持有一份代码——这就是 fork 的技术理由（已核实 v0.23.0 仍如此）。
- **样式现状**：面板内联注入自己的 CSS，类名前缀 `dig-`；颜色混用上游自己的变量与 `--dsw-alias-*`；行高/字号按上游密度；无 `--workbench-*` token。
- **工作台 token**（设计稿 §2.0b，已在 `src/styles/tailwind.css` 落地）：面板底 `#F3F4F6`/`#15161A`、侧栏 `#FAFAFB`/`#191A1F`、编辑器白/`#1C1D22`、边框 `#E3E5EA`/`#2A2C33`、主色 `#3B6FF5`/`#5B8CFF`、增 `#1A7F37`/`#3FB950`、删 `#CF222E`/`#F0616D`、标签 `#9A6700`/`#D6A84A`、远程 `#8250DF`/`#A97BF5`；密度 11–13px / 行高 22–30px；滚动条 6px。

## Key Decisions

- **D1 冻结同步**：不再 `git clone` 上游、不再重放补丁。`src/git/UPSTREAM.md` 保留来源、版本、MIT 署名与「我们改了什么」，删除「同步步骤」章节，改写为「当前所有权规则：直接改，改完更新本文件的变更表」。
- **D2 先样式、后结构**：第一步只做**样式层**（CSS 变量映射 + 密度 + 类名覆盖），不重写逻辑。理由是面板的行为已经被实测过（T2 验收），重写会重新引入风险；而样式是用户能立刻看见的差距。
- **D3 抽取按「收益/风险」排序，不设大爆炸重写**：每抽一块（如提交框、动作条、变更分组、分支树、diff），先让上游文件里的同名块变成对抽出来的组件的调用，保留原 props/行为，再删旧实现。图谱 lane 绘制与 git 解析逻辑最后再碰（那是纯算法，样式无关）。
- **D4 数据层不动**：宿主半（git 路由、队列、守卫）与客户端 `src/git/status.ts`（状态栏/角标摘要）保持现状；本任务只改渲染层。
- **D5 技术栈与插件一致**：TSX + Tailwind token + shadcn 原语（Button/DropdownMenu 已有）+ `cn()`；diff 与代码块高亮复用现有 shiki 实例（`src/highlight.ts`）；不新增 UI 依赖。
- **D6 明暗同构**：面板内**不出现**硬编码主题色，唯一例外是 diff 的增删底色与图谱 lane 色板——它们集中在 `src/git/theme.ts` 一处，按 `body[data-ds-dark-theme]` 两套取值。
- **D7 行为零回归**：本任务不删功能、不改端点、不改配置字段。任何视觉重排都要过一遍 T2 的验收清单（见下）。

## Requirements

- **R1 token 化**：面板内所有颜色/字号/间距改走 `--workbench-*`/`--dsw-alias-*` 或 `src/git/theme.ts` 的常量；`grep` 不出现新的十六进制颜色（`theme.ts` 除外）。
- **R2 密度对齐**：列表行 22–26px、分组头 26–28px、提交框输入 13px、按钮 24–28px、圆角 6px、滚动条 6px；与 Explorer/搜索/笔记列表同一把尺子。
- **R3 明暗两套**：浅/深切换无需刷新；代码/diff 高亮随主题（GitHub Light/Dark，与文件视图同一套）。
- **R4 布局不变**：宽容器三栏（分支树 · 图谱 · 变更/提交）、窄容器堆叠，阈值沿用上游（600 / 1.15）；动作条按可用高度收纳进 `⋯`。
- **R5 结构抽取（分阶段，可停）**：至少抽出——提交框（含 `⌘↵` / `--amend`）、变更四分组（冲突/已暂存/更改/未跟踪 + 行内操作）、动作条；抽完一块删一块旧实现，`pnpm test` 每步全绿。
- **R6 无障碍与键盘**：列表可键盘导航、动作有 `title`/`aria-label`、破坏性操作默认焦点在「取消」。
- **R7 文案**：新抽出的组件走 `src/locale.ts`；上游自带的多语言字典继续服务未抽取部分，不混用。
- **R8 署名**：`NOTICE.md` + `src/git/LICENSE` 保留（MIT）；文件头部注明「基于 v0.21.1，已分叉维护」。
- **R9 体积不倒退**：抽取不得引入新依赖；`lib/client.js` gzip 增幅 ≤ 30 KB。

- [ ] `pnpm check` 全绿；39 条测试不减少（新增抽取组件的自检可加）。

## Out of Scope

- 交互式 rebase、三方冲突编辑器、submodule、LFS、blame、多仓库并行（沿用 v1 边界）。
- 宿主半（路由/队列/守卫）重写；图谱 lane 算法重写（除非抽取后发现不可维护，另立子任务）。
- push/pull 的凭据与冲突处理验证（D3 边界不变）。
- 同步上游新版本 —— 本任务的前提就是**不再同步**。

## Risks / Spikes

- **S1 上游 CSS 的覆盖成本**：面板自带样式表与内联样式混排，覆盖率可能低于预期。退路：样式阶段就把面板根节点换成 `.workbench-root` 子树并加更高优先级作用域（`#git-tab .dig-*`），仍不行的块提前进入抽取。
- **S2 抽取的边界**：单文件里的闭包依赖（`t`、`ctx`、面板内 store）可能阻止「换实现」。做法：先抽纯展示组件（props 进、事件出），有闭包依赖的块留到最后。
- **S3 图谱性能**：lane 绘制在 5k 提交量级的表现未知；抽取时保留上游的分页与虚拟滚动，不重新发明。
- **S4 diff 渲染**：上游 diff 用自带行组件与 400 KB 截断；抽出时复用 shiki，但要保留截断与「大 diff 折叠」行为。
