# v0.3-E 资源管理器：左右分栏与内部 tab

父任务：`11-05-v03-iteration`（v0.3 迭代，E 组）。

## Goal

资源管理器从"一条树，点文件就在顶层开新 tab"改成 IDE 式分栏：左树、右内容，文件在右侧**内部标签**里打开；同时补上滚动到顶/底与文件树排序。

## 已确认事实

- 旧实现：`ExplorerView` 只有一棵树，`onOpen` 直接 `openFile` → 每点一个文件就多一个顶层 tab。
- `FileView` 已是现成的只读预览（分页 800 行、支持 `line`/`stamp` 定位），可以直接嵌进内部标签复用。
- 宿主 `workspaceFiles.list` 只返回 `{ name, type }`，**没有 mtime**，所以"按修改时间排序"要另开接口，本轮不做。

## Requirements

1. 左右分栏：左列 280px 树 + 分隔边框，右侧内容区。
2. 文件在右侧内部标签打开：同路径去重、关闭活动标签后落到相邻标签、点树上的文件高亮对应行。
3. 右键菜单保留「在编辑器标签中打开」，主路径走内部标签。
4. 文件树排序：名称 A→Z / Z→A，目录始终在前。
5. 树滚动区右下角悬浮「滚动到顶部 / 底部」按钮。

## Acceptance Criteria

- [x] 点树里的文件不再新增顶层 tab，而是在右侧内部标签打开；重复点击同一文件不产生第二个内部标签。
- [x] 关闭内部活动标签后自动切到相邻标签；全部关掉回到空态提示。
- [x] 排序切换后目录仍在前，文件名顺序符合选中的方向。
- [x] 树滚动超过一屏后，右下角两个悬浮按钮可定位到顶/底。
- [x] `pnpm typecheck` / `pnpm test` 通过。

## Non-goals

- 不做按修改时间排序（宿主 `workspaceFiles.list` 不返回 mtime，需要先扩展宿主接口）。
- 不删除顶层「文件」tab：QuickOpen、搜索命中、会话里的文件引用仍然用它。
- 不做内部标签的拖拽/拆分（那是 C 组的 tab 拆分范畴）。
- 不做左右分栏宽度拖拽（固定 280px 够用；需要时再加）。
