# T2 — Git Client with Commit Graph (JetBrains 风格)

## Goal

把 fork 进来的 `dsh-ide-git`（MIT，v0.21.1）宿主半与客户端面板接进 Workspace：注册 `git` tab 类型，得到一个 **JetBrains 式 Git 工具窗口** —— 左侧 IDEA 动作条 + 分支树 + 提交列表/图谱 + 变更分组与提交框同屏。配置项进插件配置页的 Git 分组。

父任务：`10-29-workbench-plugin`（fork 策略见 `design.md` §3.4，配置页见 §2.0f）。依赖 T1 的 `workbenchTabs` 注册契约。

## Requirements

- **R2.1 接入与注册**：宿主半以 `ctx.plugin(gitHost)` 挂载并保留 `/dsh-ide-git/api/<method>` 前缀路由；客户端面板注册为 `workbenchTabs` 的 `git` 类型（`contentId: 'git:<repoRoot>'`，幂等）；不依赖 `dsh-better-sidebar`，也不占用项目侧栏（分支树与变更都在 tab 内部）。
- **R2.2 仓库识别**：以当前会话工作区为 `cwd` 定位仓库根（工作区可为仓库子目录）；非 git 仓库显示空状态；`git` 不存在/超时/非仓库分别返回可读错误码。
- **R2.3 分支树**：`HEAD / 本地 / 远程 / 标签` 分组、可折叠、过滤框、当前分支星标、ahead/behind 角标、worktree 占用标记；本地蓝 / 远程紫 / 标签黄 / HEAD 绿。
- **R2.4 提交列表与图谱**：列序对齐 IDEA（日期 → 提交人 → 图谱 → 分支标签 → 提交信息）；lane 拓扑连线、HEAD 空心点、refs 徽章（最多 3 + `+n`）；分页/无限滚动（120/页）；筛选（文本/哈希、分支或标签、提交人、日期、排序方向）。
- **R2.5 提交详情与 diff**：完整提交信息、作者/日期、变更文件列表（+/− 行数）、点文件看逐行 diff（行号 + hunk 高亮 + 红绿底 + 复制/换行工具栏）；diff 高度可拖拽并记忆。
- **R2.6 变更与提交**：冲突 / 已暂存 / 更改 / 未跟踪 四分组，行内暂存/取消暂存/丢弃，分组级全量操作；提交框多行 + `Ctrl+Enter` + `--amend`。
- **R2.7 动作条**：IDEA 式竖排（宽容器）或顶栏下一行横排（窄容器），按可用空间收纳进 `⋯`，末尾 `⚙` 可排序与显隐；按钮按状态点亮/置灰。
- **R2.8 状态栏与角标联动**：状态栏左侧显示当前分支与 `+n/−n` 改动摘要，点击切到 Git tab；未提交改动数作为 tab 标题旁角标。
- **R2.13 配置项**：AI 提交信息开关与模型/推理强度、动作条顺序与显隐、提交后自动刷新、diff 上下文行数、大 diff 截断阈值、实验性远程操作开关，全部落在插件配置页「Git」页（§2.0f）。
- **R2.9 布局自适应**：面板容器宽度 ≥600px 且宽 ≥ 高×1.15 时三栏（分支树 · 提交图谱 · 变更与提交），否则纵向堆叠；用 `ResizeObserver` 量自身尺寸，不猜容器。
- **R2.10 远程操作边界**：`fetch` 可见可用；`push` / `pull` 默认从动作条与分支右键中隐藏，仅在 `config.experimentalRemoteOps=true` 时出现（D3）。
- **R2.11 安全与守卫**：保留上游全部守卫 —— argv 数组 spawn（无 shell 字符串）、ref 不以 `-` 开头、无控制字符、路径不越出仓库、同仓写操作串行、破坏性操作 `confirm: true` 二次确认、删除分支/贮藏 30 分钟内可撤回、`main/master/trunk` 删除需输入分支名。
- **R2.12 上游同步**：`src/git/UPSTREAM.md` 记录同步基线与我们的改动点；改动集中在一处适配层（注册改造、配置合并、远程操作隐藏），不在上游组件内部散改。

## Acceptance Criteria

- [x] 在含改动的仓库里打开 `git` tab：分支名与改动文件列表与 `git status` 一致（含 untracked），且与状态栏摘要、tab 角标一致。
- [x] 面板同屏可见：分支树 + 提交列表（带 lane 图谱）+ 变更分组 + 提交框（752×479 实测 columns 三栏）。
- [x] 双击改动文件显示 diff（上游内嵌窗格），增删着色与行号沿用上游实现；diff 高度拖拽沿用上游 `paneStyle('diff')` 持久化（未单独回归）。
- [x] 暂存单文件后该文件从「更改」移到「已暂存」（已暂存 1 / 更改 6），取消暂存后复原；提交链路未在真实仓库验证（避免污染工作树），只验证了宿主方法表与 UI 按钮态。
- [ ] 在带 merge 提交的仓库上图谱 lane 正确；标签/远程分支徽章正确；点击任一提交能看详情与 diff。
- [x] `⚙`（打开插件设置）存在，动作条顺序/显隐走设置卡动作条分组（上游实现，写入 row config）；400px 收纳未单独回归。
- [x] `push` / `pull` 默认不可见（动作条 / 右键菜单 / 提交框三处），宿主同样 403 `disabled-by-config`；设置页打开开关后立即可见，关回即消失。`fetch` 断网提示未验证。
- [ ] 破坏性操作（丢弃改动、删除分支）先弹确认且焦点默认在「取消」；删除分支后出现可撤回提示，点撤回能恢复。
- [x] 非 git 工作区返回可读错误码（测试覆盖）；空仓库（`git init` 无提交）已修成「分支 + 空历史」而非报错。无 `git` 可执行文件 / merge 进行中两条未验证。
- [ ] 大仓库（>5k 改动文件 / >50k 提交）下 status 与 log 有分页/截断提示，UI 不卡死。（上游按 120/页分页 + 400KB diff 截断，未在超大仓库实测）
- [x] 关闭 `git` tab 再打开不重复挂载：宿主半在 `apply` 里挂一次（child fiber），客户端 `gitModule()` 记忆化、`apply` 只调一次。

## Out of Scope

- 交互式 rebase、三方冲突解决编辑器、submodule、LFS、blame/文件历史、worktree 视图。
- 凭据管理与 push/pull 的可用性验证（仅保留代码与开关）。
- 多仓库同时管理（一次只针对当前会话工作区所在仓库）。

## Dependencies / Risks

- 依赖 T1 的 `workbenchTabs` / `views` 契约；依赖父任务 §1b 的 vendor 完成。
- 若 S5（ui-primitives）不可用：diff 与文件图标走自带降级渲染（上游已如此设计）。
- 若 S6（改造后跑不通）：收敛为「先接 summary/branches/log 三方法」，其余功能逐步放开；最终退路是「只依赖 dsh-ide-git + 跳转入口」。
